Module 1 - HTML Fundamentals

What HTML does

HTML gives a browser the structure and meaning of a page. A document starts with a doctype, then an html root, a head for metadata and linked resources, and a body for visible content. Elements use tags; attributes add information such as a link destination or image alternative text. Nest elements according to their meaning, not just their appearance.

Core concepts

  1. Document skeleton: doctype, html, head, title, body.
  2. Elements, start/end tags, attributes, and valid nesting.
  3. Headings, paragraphs, line breaks, and thematic breaks.
  4. Links with relative paths, external URLs, fragments, and target behavior.
  5. Images with src, alt, width, and height; write alt text for informative images.
  6. Ordered, unordered, and description lists.
  7. Forms with labels, text/email/password/number inputs, radio, checkbox, select, textarea, and buttons.
  8. Semantic landmarks: header, nav, main, section, article, aside, footer.
Example - semantic structure
<header><h1>Student Portal</h1></header>
<main>
  <section aria-labelledby="courses-title">
    <h2 id="courses-title">My courses</h2>
    <p>Choose a course to continue.</p>
  </section>
</main>
Practice task

Create a student registration form with name, email, password, gender, course selection, associated labels, and submit button.

HTML self-check

Which element should contain the page's primary unique content?

Correct. Use one main landmark for the dominant content of the document.

Review the semantic HTML section. The correct answer is <main>.

Module 2 - CSS Fundamentals

How CSS styles a page

CSS rules match HTML elements with selectors and assign property/value declarations. External stylesheets keep presentation separate from document content and make shared design rules easier to maintain. The cascade resolves competing declarations through origin, importance, specificity, and source order. Prefer reusable classes and design tokens over repeated one-off values.

Core concepts

  1. Inline, internal, and external CSS; when an external stylesheet is appropriate.
  2. Element, class, ID, universal, grouped, and attribute selectors.
  3. Foreground, backgrounds, images, and contrast.
  4. Font family, size, weight, text alignment, decoration, and line height.
  5. Box model: content, padding, border, margin, width, and box-sizing.
  6. Display modes, normal flow, and positioning.
  7. Flexbox for one axis; Grid for rows and columns; use gap for spacing.
  8. Pseudo-classes such as hover, focus, active, and first-child.
  9. Stacking contexts and z-index.
Example - reusable card style
.course-card {
  padding: 1rem;
  border: 1px solid #dce5dc;
  border-radius: 8px;
  background: white;
}
Practice task

Create a student profile card and a three-column desktop layout using CSS Grid. Keep spacing, color, and type styles reusable.

CSS self-check

Which property creates space inside an element's border?

Correct. Padding is inside the border; margin is outside it.

Review the box model. The correct answer is padding.

Module 3 - Responsive Design

Design for changing screens

Responsive design lets a layout adapt to the available space, input method, and content. Begin with flexible tracks and intrinsic sizing, then add breakpoints when the composition needs to change. A responsive page should preserve reading order, keyboard access, and useful controls instead of simply shrinking a desktop canvas.

Core concepts

  • Mobile-first constraints, flexible widths, max-width, and minmax().
  • Media-query breakpoints based on content needs.
  • Responsive images and text that wraps without overflow.
  • Mobile navigation and touch target spacing.
  • Test at phone, tablet, and desktop widths.
  • Respect prefers-reduced-motion and preserve visible focus.
Example - content-driven breakpoint
.course-grid { display: grid; grid-template-columns: repeat(3, 1fr); gap: 1rem; }
@media (max-width: 700px) {
  .course-grid { grid-template-columns: 1fr; }
}
Practice task

Make a course dashboard move from three columns to one on a phone. Confirm there is no horizontal scrolling and the navigation remains reachable.

Responsive design self-check

When should a layout breakpoint be chosen?

Correct. Let the content and layout needs determine breakpoints.

Choose the point where the composition needs to change.

Module 4 - JavaScript Basics

Browser behavior and programming basics

JavaScript adds behavior to the browser interface. A script can read input, update the DOM, and react to events. Use const for bindings that are not reassigned and let when reassignment is needed. Keep functions focused, validate form data, and show feedback near the control that needs attention.

Core concepts

  1. JavaScript's role alongside HTML and CSS.
  2. var, let, const; strings, numbers, booleans, undefined, null, objects, and arrays.
  3. Arithmetic, comparison, logical, and assignment operators.
  4. if/else, switch, for, while, and do-while.
  5. Functions, arguments, parameters, and return values.
  6. Arrays and push, pop, shift, unshift, slice, splice.
  7. Objects and property access.
  8. DOM selection and event handling.
  9. Form validation, accessible status messages, and error states.
Example - validate a required value
const nameField = document.querySelector("#name");
if (nameField.value.trim() === "") {
  nameField.setCustomValidity("Enter your name.");
}

Module 1 - Python Fundamentals

Start with values and control flow

Python programs are interpreted instructions. Variables name values, and types tell Python what operations make sense. input() returns text, so convert values before numeric work. Conditional branches choose a path; loops repeat a task. Indentation defines the blocks that belong to each statement.

  • Install Python, use the interpreter, run scripts.
  • Variables, int/float/str/bool/complex.
  • input(), print(), conversions, and operators.
  • if/elif/else, for/while, break/continue/pass.
Example - grade from marks
marks = float(input("Marks: "))
if marks >= 85:
    grade = "A"
elif marks >= 60:
    grade = "Pass"
else:
    grade = "Practice more"
print(grade)
Practice task

Extend the program to validate marks from 0 to 100 and explain how the boundary values are handled.

Python fundamentals self-check

What type does input() return before conversion?

Correct. Convert the string before numeric calculations.

Module 2 - Python Data Structures

Choose a collection for the job

Lists preserve order and can change; tuples preserve order but are immutable; sets hold unique values; dictionaries associate keys with values. The right choice makes updates and lookups easier to express. Nested structures are useful, but named records or classes can make complex data clearer.

  • List mutation and sorting methods.
  • Tuple indexing, slices, packing, and unpacking.
  • Set operations: union, intersection, and difference.
  • Dictionary keys, values, items, get, and update.
Example - count values
counts = {}
for name in ["Ari", "Mina", "Ari"]:
    counts[name] = counts.get(name, 0) + 1

Module 3 - Strings

Text as a sequence

Strings are immutable sequences of Unicode characters. Indexing selects one position; slicing selects a range. Methods such as strip(), lower(), replace(), split(), join(), find(), and count() support common transformations. Normalize case and whitespace before comparisons, and be explicit about punctuation rules.

Example - normalize a name
raw_name = "  maya chen "
name = raw_name.strip().title()

Module 4 - Functions

Inputs, work, and returned results

Functions name reusable operations. Parameters define the inputs; return sends a result back to the caller. Default and keyword arguments make optional inputs clearer. *args collects extra positional values and **kwargs collects named values. Keep functions focused, and use recursion only when its base case and call depth are understood.

Example - calculator operation
def divide(left, right):
    if right == 0:
        raise ValueError("Cannot divide by zero")
    return left / right
Practice task

Module 5 - Object-Oriented Programming

Model behavior and state

A class describes a kind of object; an instance holds data and can use methods defined by its class. __init__ initializes instance state. Encapsulation keeps internal details behind intentional operations. Inheritance shares or specializes behavior, while composition combines collaborating objects. Prefer simple designs that reflect real responsibilities.

Example - course object
class Course:
    def __init__(self, title):
        self.title = title

    def display_name(self):
        return self.title.strip()

Module 6 - Exception Handling

Make failure understandable

Exceptions signal that an operation could not proceed normally. Put risky operations in try, handle specific expected exceptions in except, and use else for work that should happen only after success. finally is for cleanup. Raise a clear exception when a function cannot meet its contract.

Example - validate numeric input
try:
    age = int(raw_age)
except ValueError:
    print("Enter a whole number.")
Practice task

Exception handling self-check

Which block runs whether an exception occurred or not?

Module 7 - File Handling

Persist data beyond one run

Files store data outside a program's memory. Use a context manager so a file is closed reliably. Read mode expects an existing file; write mode replaces content; append adds content. CSV works for tabular records and JSON for nested data. Validate parsed input because file contents can be malformed.

Example - safe text write
with open("notes.txt", "w", encoding="utf-8") as file:
    file.write("Review Python functions\\n")

Module 8 - Advanced Python

Organize reusable code

Comprehensions build collections from iterables. Iterators provide values one at a time; generators can produce values lazily. Decorators wrap behavior around functions. Modules and packages organize code for reuse. A virtual environment isolates project dependencies, while pip installs packages into that environment.

Example - filtered comprehension
passed = [score for score in scores if score >= 60]

Describe persistent application data

Module 11 - Django Authentication

Use framework authentication safely

Authentication verifies identity; authorization determines what an authenticated user may do. Django provides password hashing, sessions, login/logout helpers, and permission tools. Do not store plain-text passwords or trust a role supplied by an untrusted browser form. Protect state-changing requests and restrict student/admin views on the server.

  • Registration and profile workflows.
  • Sign-in, sign-out, sessions, and password resets.
  • Permissions, role checks, CSRF protection, and safe redirects.

Module 1 - Database Fundamentals

How relational data is organized

A database stores information; a DBMS manages access, consistency, and queries. An RDBMS organizes related records into tables. A row represents one record and a column one attribute. SQL is a language for defining and querying relational data; MySQL is one RDBMS implementation.

Example - student table
id | name | email
1  | Ari  | ari@example.com
2  | Mina | mina@example.com
Practice task

List the entities needed to track students, courses, enrollments, and completed concepts.

Database fundamentals self-check

In a relational table, a row usually represents:

Correct concept: a row stores one record. Recheck the answer key if needed.

A row is a record; a column describes one attribute.

Module 2 - SQL Fundamentals

Define and query tables

SQL statements are grouped by purpose. DDL defines structures, DML changes records, and SELECT retrieves them. Use a WHERE clause to target the intended records; inspect a SELECT first when preparing an UPDATE or DELETE.

  • DDL: CREATE, ALTER, DROP, TRUNCATE.
  • DML: INSERT, UPDATE, DELETE.
  • DQL: SELECT, filtering, sorting, and column selection.
Practice task

Create a simple students table, insert sample records, and query one student's email.

SQL self-check

Which statement retrieves rows?

Correct. SELECT reads data from tables or query results.

SELECT retrieves records; DROP removes a database object.

Module 3 - Constraints

Protect data integrity

Constraints let the database reject invalid states. A primary key identifies a row. A foreign key references a related row. UNIQUE, NOT NULL, DEFAULT, and CHECK constraints describe additional rules. Constraints matter even when the application already validates input.

Example - required unique email
CREATE TABLE students (
  id INT PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(100) UNIQUE
);
Practice task

Add an enrollment table with student and course foreign keys and a uniqueness rule for each student/course pair.

Constraints self-check

What does a foreign key help enforce?

Foreign keys connect related records across tables.

Module 4 - CRUD

Create, Read, Update, Delete

CRUD describes the four basic data operations. INSERT creates rows; SELECT reads them; UPDATE changes matched rows; DELETE removes matched rows. Use parameterized queries in application code and precise conditions to avoid unintended data changes.

Example - targeted update
UPDATE students
SET name = 'Ari Chen'
WHERE id = 1;
Practice task

CRUD self-check

Which clause limits which rows an UPDATE changes?

Module 5 - SQL Operators

Filter values precisely

Comparison and logical operators combine conditions. BETWEEN describes a range; IN checks membership in a set of values; LIKE matches text patterns; IS NULL tests missing values. SQL NULL represents unknown or absent data, so equality comparisons are not suitable for detecting it.

Example - range and missing value
SELECT name FROM students
WHERE marks BETWEEN 60 AND 100
  AND graduation_date IS NOT NULL;

Which predicate checks for a missing SQL value?

Module 6 - Aggregate Functions

Summarize a set of rows

Aggregate functions turn many values into a summary. COUNT counts rows or non-NULL values depending on its expression. SUM and AVG calculate totals and means; MIN and MAX find boundaries. Know how NULL values affect the chosen expression.

Example - average score
SELECT AVG(score) AS average_score
FROM course_results;

Which function calculates the mean?

Module 7 - GROUP BY and HAVING

Summarize by category

GROUP BY partitions rows by one or more values before applying aggregates. WHERE filters individual rows before grouping; HAVING filters the resulting groups. Every selected non-aggregated column generally belongs in the grouping criteria.

Example - enrollments per course
SELECT course_id, COUNT(*) AS learners
FROM enrollments
GROUP BY course_id
HAVING COUNT(*) >= 10;
Practice task

Count passed assessments per course and show only courses with at least five passes.

GROUP BY self-check

Which clause filters aggregated groups?

Correct. HAVING filters groups after aggregation.

WHERE filters rows; HAVING filters grouped results.

Module 8 - Joins

Combine related tables

Joins connect rows using related columns, often primary and foreign keys. INNER JOIN keeps matching rows; LEFT JOIN keeps every left-side row and adds matching right-side values when available. RIGHT JOIN and CROSS JOIN have different use cases. Always verify join keys and row counts.

Example - student enrollments
SELECT students.name, courses.title
FROM students
JOIN enrollments ON enrollments.student_id = students.id
JOIN courses ON courses.id = enrollments.course_id;
Practice task

List every student and their enrolled course; include students who have no enrollment yet.

Joins self-check

Which join keeps every row from its left table?

Correct. LEFT JOIN preserves left-side rows with or without a match.

INNER JOIN keeps only matches; LEFT JOIN preserves left rows.

Module 9 - Subqueries

Use a query inside a query

A subquery provides a result to an outer query. Scalar subqueries return one value; multi-row subqueries can be used with IN or EXISTS. Prefer a join or common table expression when it makes the intent clearer. Check query plans for large datasets.

Example - above-average marks
SELECT name
FROM students
WHERE marks > (SELECT AVG(marks) FROM students);
Practice task

Find courses whose average assessment score is above the overall average.

Subqueries self-check

What does a scalar subquery return?

Scalar means a single value.

Module 10 - Normalization

Reduce duplication and anomalies

Normalization organizes facts into tables so updates remain consistent. First normal form requires atomic values and rows that can be identified. Second normal form removes partial dependency on part of a composite key. Third normal form removes inappropriate transitive dependencies. Use constraints and keys to make relationships explicit.

  • 1NF, 2NF, and 3NF.
  • Functional dependencies and candidate keys.
  • Insertion, update, and deletion anomalies.
Practice task

Normalize a spreadsheet that repeats student, course, and instructor information across many rows.

Normalization self-check

What problem does normalization primarily reduce?

Correct. Normalization structures facts to reduce anomalies.

Think about duplicated facts and inconsistent updates.
