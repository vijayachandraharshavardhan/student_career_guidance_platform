Course curriculum

Concept → practice → project

Module 1 · Java syntax and core types

Learn

Understand the JDK, compiler, JVM, source files, packages, and main entry point. Java declares types before variables; primitive values include int, double, boolean, and char, while String represents text.

Example
public class HelloCareer {
  public static void main(String[] args) {
    String goal = "Build useful software";
    System.out.println(goal);
  }
}
Practice

Create a class that prints your learning goal and one skill you want to develop.

Self-check

Where does Java bytecode run?

Correct. The JVM executes Java bytecode.

Review the runtime: bytecode runs on the JVM.

Module 2 · Conditions, loops, and methods

Learn

Use if/else and switch to branch, loops to repeat, and methods to group behavior. Method signatures include a return type, name, and parameters. Use equals() to compare String content.

  • Comparison and Boolean operators.
  • for, enhanced for, while, and break/continue.
  • Parameters, return values, scope, and overloads.
Practice

Write a method that classifies a score and returns a grade label.

Self-check

How should Java strings usually be compared by content?

Correct. equals() compares String contents.

Use equals() for String content equality.

Module 3 · Object-oriented programming

Learn

Classes define state and behavior; objects are instances. Constructors initialize objects. Encapsulation protects fields behind methods. Interfaces specify capabilities, and composition lets objects collaborate without forcing deep inheritance.

  • Constructors, access modifiers, and immutable fields.
  • Inheritance, overriding, abstract classes, and interfaces.
  • Prefer composition where it keeps responsibilities clear.
Practice

Design Student and Course classes with private fields and methods that express their responsibilities.

Self-check

What is an object?

Correct. An object is an instance created from a class.

A class describes a type; an object is one instance.

Module 4 · Collections, generics, and exceptions

Learn

Use List for ordered values, Set for uniqueness, and Map for key/value lookup. Generics such as List<String> make element types explicit. Exceptions let code report and handle failures.

  • ArrayList, HashSet, HashMap, iteration, and generics.
  • try/catch/finally and specific exception types.
  • Validate input at system boundaries.
Practice

Store course titles in an ArrayList and handle invalid numeric input with a specific exception.

Self-check

Which interface commonly represents an ordered collection?

Correct. List represents an ordered collection.

Use List for ordered values.

Module 5 · Git, Maven, and project structure

Learn

Git records project history; Maven describes dependencies and repeatable build steps. Organize packages by responsibility and keep environment-specific settings outside committed secrets.

  • Repository, commit, branch, merge, and ignore rules.
  • Maven coordinates, dependencies, lifecycle, and tests.
  • Readable package layout and configuration.
Practice

Create a small Maven project, add one dependency, and commit a documented first version.

Self-check

What is a Maven dependency used for?

Correct. Dependencies declare libraries for the build.

Maven dependencies declare libraries the project needs.

Module 6 · HTML, CSS, and JavaScript foundations

Learn

Build browser interfaces with semantic HTML, maintainable CSS, and event-based JavaScript. Use responsive layouts, accessible names, and visible focus. Keep behavior separate from markup where possible.

  • Forms, semantic landmarks, responsive layout, and keyboard support.
  • DOM selection, event listeners, and client-side validation.
Practice

Create an accessible registration form and adapt its layout to a phone.

Self-check

Which element is appropriate for a user-triggered action?

Correct. Use a button for an action.

Choose the semantic control for actions: button.

Module 7 · SQL and relational database design

Learn

Relational databases store records in tables with keys and constraints. Plan entities and relationships before writing queries. Understand SELECT, joins, indexes, transactions, and normalization basics.

Practice

Model students, courses, and enrollments with primary and foreign keys.

Self-check

What does a foreign key represent?

Correct. Foreign keys connect related records.

Foreign keys represent relationships between rows.

Module 8 · Spring Boot application foundations

Learn

Spring Boot reduces setup for Java services. Dependency injection supplies collaborators, configuration describes environments, and application layers divide web, business, and persistence responsibilities.

  • Starters, auto-configuration, beans, and dependency injection.
  • Configuration properties and profiles.
Practice

Create a Spring Boot application with one service injected into a controller.

Self-check

What does dependency injection do?

Correct. The framework supplies configured dependencies.

Dependency injection provides a component with its collaborators.

Module 9 · REST APIs with Spring MVC

Learn

Controllers map HTTP requests to application operations. DTOs shape data at the API boundary. Return meaningful status codes, validate inputs, and provide consistent error responses.

Practice

Design endpoints for listing courses and submitting a quiz result, including request and response examples.

Self-check

What should a DTO primarily represent?

Correct. DTOs define data transferred across boundaries.

DTO means data transfer object.

Module 10 · Persistence with JPA and Hibernate

Learn

JPA maps Java entities to relational tables. Repositories provide data access; relationships model associations. Transactions group changes so related operations commit or roll back together.

  • Entity identifiers, columns, and relations.
  • Repositories, queries, migrations, and transaction boundaries.
Practice

Model a student enrollment relation and choose which fields require uniqueness.

Self-check

What does a transaction help ensure?

Correct. Transactions protect grouped data changes.

Transactions define an all-or-nothing unit of work.

Module 11 · Authentication and application security

Learn

Authentication establishes identity; authorization checks permissions. Hash passwords with a trusted framework, keep secrets out of source control, validate inputs, and protect state-changing requests.

  • Roles, permissions, sessions, CSRF, and safe configuration.
  • Security checks belong on the server, not only in the UI.
Practice

Write an access matrix for student, instructor, and admin actions in a course portal.

Self-check

Where should access permissions be enforced?

Correct. UI visibility is not a security boundary.

The server must verify each protected action.

Module 12 · React frontend integration

Learn

React components compose interface pieces. Props pass data, state represents changing UI data, and API calls provide server-backed information. Handle loading, errors, and empty data states explicitly.

Practice

Build a course list view that shows loading, empty, success, and failure states.

Self-check

What is React state used to represent?

Correct. State represents changing interface data.

Props are inputs; state is changing component data.

Module 13 · Testing and observability

Learn

Unit tests check small behaviors; integration tests cover collaborating components; API tests verify request/response contracts. Logs and health checks help diagnose a running service.

Practice

Write tests for a service method and one controller validation error.

Self-check

What is an integration test designed to examine?

Correct. Integration tests exercise component interactions.

An integration test checks collaborating components.

Module 14 · Capstone and deployment

Build and ship a coherent application

Plan a useful product slice, implement the frontend and API, persist data, test the core flows, and document how to run it. Deployment includes configuration, secrets, health checks, and a rollback plan.

  • Project scope, user stories, and architecture.
  • Automated tests, environment configuration, and deployment.
  • README, screenshots, API notes, and demo presentation.
Capstone

Build a course portal with a React client, Spring API, relational data, and documented tests.

Self-check

What should a deployment README provide?

Correct. Document reproducible setup and operation.

A useful README explains setup, tests, and running the app.
